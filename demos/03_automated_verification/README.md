# 示範 03：自動化驗證（兩趟逐位元比對＋突變測試）

**問題**：大樣本時，把每一轉的完整事件留在記憶體跑不動，所以「配平趟」只算賠付數值，
「產出趟」才建立完整 books。但兩趟若走不同的路，產出的 books 就可能和配平時的數字**對不上帳**。

**解法**：兩趟呼叫**同一個** `play()`，只差一個旗標；再用逐位元比對把關。

## 設計要點

1. **每本 book 以 (seed, book_id) 獨立播種** → 結果與計算順序無關、可重現。
2. **事件產生不得消耗亂數**（純函式）。否則兩趟的亂數序列會發散。
3. **驗證器只看輸出**（books、查找表、賠付表），不 import 遊戲引擎，避免「引擎寫錯、斷言跟著錯」。

## 檢查項目

| 檢查 | 擋什麼 |
|---|---|
| 兩趟逐位元相同 | 配平與產出不一致、事件產生偷耗亂數 |
| 可見＝實付：由盤面＋公布賠付表重算賠付 | 合成 book、改金額不改盤面、輸出端縮放係數 |
| 事件順序與 finalWin 一致 | 事件順序寫反、結算金額不一致 |
| 查找表與 books 逐筆一致、權重為正整數 | 查找表被改、權重為 0 或非整數 |
| RTP 恆等式：Σ(賠付×權重)/Σ權重 | 宣稱的 RTP 與實際不符 |

## 結果（`python run.py`）

乾淨資料 5,000 本：5 項全 PASS。**故意弄壞 5 種東西，5 種全部被擋下**：

| 突變 | 驗證器的回應 |
|---|---|
| 事件產生偷耗一次亂數 | `兩趟賠付不同：3137 本（例：id=0）` |
| 只改 book 金額、不改盤面 | `可見≠實付：book 0 盤面算出 125，入帳 225` |
| 輸出端縮放係數 win×0.96 | `可見≠實付：book 0 盤面算出 125，入帳 120` |
| 查找表某筆賠付差 1 | `id 10 查找表賠付 101 ≠ books 100` |
| 宣稱的 RTP 差 0.05 個百分點 | `RTP 恆等式不成立：…` |

`tests/test_verify.py` 把這些寫成 pytest（共 9 個），其中 7 個是突變測試。

## 為什麼要「突變測試」

一個從沒失敗過的檢查，你不知道它是真的在檢查，還是恆真。故意弄壞、確認它會紅，才能信任它變綠的意義。

## 限制

- 虛構遊戲只有單一盤面事件；真實遊戲的事件串更長，還需檢查事件粒度、封頂後不再演出等行為。
